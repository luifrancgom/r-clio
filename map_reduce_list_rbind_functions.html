20  Funciones map(), reduce() y list_rbind()

Este capítulo se basa en (Wickham, 2023, Capítulo 26) así como en la documentación oficial de purrr donde tiene como propósito introducir la forma de consolidar múltiples archivos que se encuentran en un directorio, utilizando el paquete purrr e información de los resultados del examen Saber Pro del grupo de competencias genéricas correspondientes a programas de pregrado de la Universidad Militar Nueva Granada (UMNG).

Exploraremos los siguientes aspectos:

  1. ¿Cómo importar múltiples archivos en un directorio utilizando el paquete purrr?
  2. ¿Cómo consolidar múltiples tablas de datos por filas en un solo archivo utilizando el paquete purrr?
  3. ¿Cómo utilizar la gramática de manipulación de datos (ver Capítulo 10 y Capítulo 11) para limpiar y exportar un archivo consolidado?

20.1 Importación

Cuando se trabaja con datos históricos, es común que la información se encuentre fragmentada en múltiples archivos dentro de un mismo directorio donde cada archivo corresponde a un año o periodo determinado. Para procesar estos archivos sin necesidad de repetir manualmente las instrucciones de importación una y otra vez, es posible combinar herramientas de exploración del sistema de archivos con funciones de iteración del paquete purrr.

Para gestionar rutas y archivos en un sistema operativo, utilizarás el paquete fs. El paquete fs ofrece una interfaz homogénea, consistente e independiente del sistema operativo, que se integra de manera natural con el operador |> y las funciones del tidyverse.

En particular, la función dir_ls() del paquete fs lista los contenidos de un directorio aplicando criterios específicos de filtrado (ver Listado 20.1). Sus parámetros principales son:

  1. path: la ruta del directorio que se desea explorar, como por ejemplo "data/".

  2. type: el tipo de elemento a buscar. Al especificar por ejemplo type = "file" se restringe la búsqueda exclusivamente a archivos, descartando posibles subcarpetas.

  3. glob: un patrón de texto basado en caracteres comodín (en inglés wildcards) para seleccionar los archivos que cumplen con un patrón determinado. Por ejemplo, en el patrón "*.txt.xz$":

    • El asterisco * actúa como comodín para representar cualquier secuencia de caracteres de longitud variable como por ejemplo 2021-saber_pro-genericas.
    • .txt.xz señala la extensión compuesta de los archivos comprimidos de texto plano.
    • El símbolo $ ancla la búsqueda garantizando que únicamente se seleccionen archivos cuya denominación termine con esa extensión exacta.

En el Listado 20.4 conviene destacar el uso de la función auxiliar all_of(), perteneciente al paquete tidyselect (integrado en el tidyverse y utilizado por readr en argumentos como col_select). Su empleo cumple dos propósitos fundamentales:

  1. Resolución explícita de variables de entorno: El argumento col_select opera mediante evaluación ordenada (tidy selection), lo que permite seleccionar columnas directamente por su nombre o mediante expresiones de selección. Cuando se suministra un vector de caracteres definido en el entorno de trabajo como variables_completas, envolverlo en all_of() le indica a R de forma inequívoca que debe evaluar el contenido de dicho vector como los nombres de las columnas a seleccionar. Esto evita advertencias y previene ambigüedades entre las variables de los datos (data-variables) y las variables del entorno (env-variables).

  2. Validación estricta de columnas: all_of() exige que todas las columnas especificadas en el vector existan en el archivo que se está leyendo; si falta alguna, la función interrumpe la ejecución y emite un error. Esta rigurosidad garantiza la integridad del proceso de importación frente a su alternativa any_of(), que selecciona las columnas coincidentes e ignora silenciosamente las ausentes. Al usar all_of(variables_completas), aseguras que las 82 variables comunes identificadas se carguen efectivamente en la totalidad de los archivos anuales.

20.4 Corrección códigos departamentos y municipios

De acuerdo con el estándar de codificación DIVIPOLA establecido por el DANE, los códigos de departamento deben poseer exactamente 2 dígitos, por ejemplo, "05" para Antioquia u "11" para Bogotá D.C., mientras que los códigos de municipio deben contar exactamente con 5 dígitos, por ejemplo "05001" para Medellín.

No obstante, al consultar la longitud en caracteres de las variables geográficas mediante la función str_length() del paquete stringr y la función count() de dplyr, se identifica que algunos registros presentan longitudes inferiores a las reglamentarias, tal como se señala en el Listado 20.11:

El resultado del Listado 20.13 demuestra que la discrepancia radica en la pérdida del cero a la izquierda en aquellos departamentos con códigos entre "01" y "09" registrados erróneamente como por ejemplo 5 en vez de "05" y municipios asociados registrados como por ejemplo 5001 en vez de "05001".

Para corregir esta anomalía y restablecer los ceros a la izquierda se utiliza la función str_pad() del paquete stringr. En manipulación de texto y cadenas de caracteres, el término padding (en español relleno) hace referencia a la acción de añadir caracteres a una cadena hasta alcanzar una longitud o ancho total deseado. Si el texto original ya cuenta con dicha longitud o la supera, str_pad() lo deja inalterado sin modificarlo.

La función str_pad() se compone de 4 argumentos clave:

  1. string: el vector o columna de texto que se desea rellenar.

  2. width: el ancho total mínimo o número de caracteres deseado para la cadena resultante. Por ejemplo, en los códigos de departamento DIVIPOLA se define width = 2, mientras que para los códigos municipales se especifica width = 5.

  3. side: el extremo o lado de la cadena donde se insertarán los caracteres de relleno para alcanzar el ancho definido en width. Este parámetro contempla 3 opciones:

    • "left": inserta el relleno a la izquierda donde antepone caracteres. Esta opción es la indicada cuando se requiere restituir ceros a la izquierda en variables numéricas o códigos estandarizados, como por ejemplo transformar "5" en "05" o "5001" en "05001".
    • "right": inserta el relleno a la derecha donde añade caracteres al final.
    • "both": distribuye el relleno de manera equilibrada a ambos lados, centrando el texto original.

  4. pad: el carácter individual con el que se rellenará el espacio faltante. Por defecto, str_pad() utiliza un espacio en blanco (pad = " "), pero en este contexto se define pad = "0" para restituir el formato numérico oficial.

De esta manera, al evaluar str_pad(string = "5", width = 2, side = "left", pad = "0") se obtiene "05", mientras que un código como "11" permanece intacto porque ya satisface el ancho mínimo de 2 caracteres. Análogamente, para los municipios con width = 5, un código incompleto como "5001" pasa a ser "05001", mientras que "11001" no sufre alteraciones.

20.5.1 Limpiar y filtrar

El primer paso comprende la gestión de los exámenes presentados fuera del país y la delimitación de la población objetivo:

  1. Estudiantes en el exterior: cuando un estudiante presenta la prueba en el exterior (estu_exterior == "SI"), los códigos de departamento y municipio colombianos no resultan aplicables. Mediante la función replace_when() en combinación con across(), se asigna el valor ausente NA a las columnas estu_cod_depto_presentacion y estu_cod_mcpio_presentacion cuando se cumple dicha condición.

  2. Población agregada oficial: se aplica filter(estu_agregado == "S") para conservar únicamente a los estudiantes evaluados formalmente como parte de la población agregada institucional válida para indicadores de calidad.

  3. Filtro institucional UMNG: se utiliza filter(inst_cod_institucion == 1117) para seleccionar exclusivamente los registros de la Universidad Militar Nueva Granada (UMNG) cuyo código oficial asignado por el SNIES es 1117.
